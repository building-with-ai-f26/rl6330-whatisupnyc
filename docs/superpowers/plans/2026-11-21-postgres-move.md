# Postgres Move (PR 1 of Supabase accounts) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every table moves from SQLite to Supabase Postgres, with the app, the collector and all 332 tests working the same as before, and the site still behind the pod password.

**Architecture:** `app/db.py` keeps its function names and return types, but takes a `psycopg_pool.ConnectionPool` instead of a `sqlite3.Connection`, and each function borrows a connection for one statement. The schema lives in one SQL migration file under `supabase/migrations/`, applied to Supabase with the Supabase CLI and to the local test database by the test fixture. A one-time script copies the production SQLite file into Postgres, keeping IDs.

**Tech Stack:** Python 3.12, `psycopg[binary,pool]` 3.x, Postgres 17 (Homebrew locally, Supabase in dev and production), Supabase CLI for migrations, pytest.

**Spec:** `docs/superpowers/specs/2026-11-21-supabase-accounts-design.md` (sections "Database", "Moving existing data", "Tests", "Docs and deploy", order-of-work step 1).

## Global Constraints

- The site stays behind the pod password in this PR; `SITE_PASSWORD` and `app/auth.py` don't change.
- `subscribers` keeps its current shape (integer `id`, `token` links) in this PR; PR 2 replaces it with `profiles`.
- Row Level Security on every table, with no policies in this PR (Supabase's public API can read or write nothing). The server's connection string is the owner role, which bypasses RLS.
- Secrets only in `.env` and `/etc/whatisupnyc/env`; `DATABASE_URL` is secret. Update `.env.example`.
- Connect through Supabase's **session pooler** (IPv4) connection string, not the direct address.
- `uv run pytest` must not touch any Supabase project. Tests use `TEST_DATABASE_URL`, default `postgresql://localhost/whatisupnyc_test`.
- No new dependency beyond `psycopg[binary,pool]`.
- Every caller of `db.*` keeps working without changing its arguments, except `db.connect`, which now takes a database URL.

## Review Focus

1. **Supabase closes an idle connection overnight.** The web app runs for days, so the next request must still work. Pinned in Task 1 by `test_pool_recovers_after_connection_is_killed`.
2. **The move script is run twice, or against a database that already has data.** It must refuse and change nothing. Pinned in Task 3 by `test_move_refuses_when_target_has_rows`.
3. **The collector saves new events after the move.** Their IDs must not collide with the copied ones (identity sequence reset). Pinned in Task 3 by `test_new_rows_after_move_get_fresh_ids`.
4. **An old SQLite reader with no token, or `days` stored as JSON text.** It must arrive with a long random token and a real list. Pinned in Task 3 by `test_move_converts_old_values`.
5. **Postgres isn't running when someone runs `uv run pytest`.** The failure must say how to start it, not dump a connection traceback. Pinned in Task 1 by the `conn` fixture's error message (checked by hand in Task 1 Step 6).

```python
def test_every_table_has_row_level_security(conn):
    with conn.connection() as c:
        rows = c.execute("select relname, relrowsecurity from pg_class where relnamespace = 'public'::regnamespace and relkind = 'r'").fetchall()
    assert {r["relname"] for r in rows} == set(db.TABLES)
    assert all(r["relrowsecurity"] for r in rows)

def test_waiting_pastes_listed_without_limit_by_default(conn):
    for n in range(3):
        db.save_waiting_paste(conn, f"https://www.tiktok.com/@a/{n}", "")
    assert len(db.list_waiting_pastes(conn)) == 3
    assert len(db.list_waiting_pastes(conn, 2)) == 2

def test_pool_recovers_after_connection_is_killed(conn):
    db.save_waiting_paste(conn, "https://www.tiktok.com/@a/1", "")
    with conn.connection() as c:
        pid = c.execute("select pg_backend_pid() as pid").fetchone()["pid"]
    with psycopg.connect(TEST_URL, autocommit=True) as killer:
        killer.execute("select pg_terminate_backend(%s)", (pid,))
    assert db.count_waiting_pastes(conn) == 1
```

- [ ] **Step 5: Port `app/db.py`**

`connect(url)` returns:

```python
ConnectionPool(url, min_size=1, max_size=4, open=True,
               check=ConnectionPool.check_connection,
               kwargs={"autocommit": True, "row_factory": dict_row, "prepare_threshold": None})
```

`prepare_threshold=None` is needed because Supabase's pooler doesn't support prepared statements.

Each function uses `with conn.connection() as c:` and `%s` placeholders. Drop every `commit()`, since autocommit is on.
- `save_event` and `save_subscriber`: return the ID with `RETURNING id`.
- `mark_sent`: `INSERT OR IGNORE` becomes `ON CONFLICT DO NOTHING`.
- Pass datetimes, booleans, lists and `date` objects straight to psycopg, with no `isoformat()` or `json.dumps`.
- Reading `start` back: `_row_to_scored` and `list_pastes` return `row["start"].astimezone(NY)`.
- `record_ai_request` and `count_ai_requests_today` use the UTC `date` (rename `_utc_day` to return a `date`).

- [ ] **Step 3: Implement `move`**

- **Check first:** before copying anything, check every table in `db.TABLES` and raise `RuntimeError("Target database is not empty: <table>")` if any has rows.
- **Read:** read SQLite with `sqlite3.Row`.
- **Copy:** insert into Postgres inside one transaction (`with target.connection() as c, c.transaction():`), so a failure copies nothing.
- **Convert:**
  - `start`: ISO text → `datetime.fromisoformat`.
  - `eligible`: 0/1 → `bool`.
  - `days`: JSON text → `list`.
  - `ai_requests.day`: ISO text → `date`.
  - A `NULL` subscriber token gets `db._new_token()`.
- **Reset IDs:** after copying, reset each identity sequence with `select setval(pg_get_serial_sequence('<t>', 'id'), coalesce(max(id), 0) + 1, false) from <t>` for every table that has an `id` column.
- **When run as a script:** print the counts.
